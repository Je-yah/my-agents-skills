# /notion-to-tistory 스킬 설계

**날짜:** 2026-11-14  
**상태:** 승인됨 (2026-11-14)  
**작성 도구:** Claude Code (superpowers:brainstorming)

---

## 개요

노션에 정리한 활동 기록(해커톤, 프로젝트, 연구, 학습 등)의 게시 링크를 입력하면, 페이지를 읽어 카테고리를 분류하고 기술 블로그(Jehye.log, mgs10204.tistory.com) 톤으로 요약·정리한 뒤, 썸네일과 본문 삽화를 생성해 티스토리 에디터에 붙여넣을 수 있는 **게시 패키지**를 만드는 스킬.

## 의도와 이유

- 활동 기록은 노션에 쌓이지만 블로그 재발행은 수동 작업이라 누락된다.
- 분류·요약·이미지까지 한 번에 처리해 "붙여넣기 2분"으로 게시 비용을 줄인다.

## Goals

1. 노션 게시 링크 입력 → 페이지 본문·이미지 구조 읽기
2. 카테고리 분류: 기존 4개 카테고리(`Devlog` / `회고` / `Paper Review` / `CS`) 중 1개 + 제목 prefix(`[Hackathon]`, `[Project]`, `[Conference]` 등) + 기술 분야 태그(복수)
3. 블로그 기존 톤에 맞춘 요약·정리 초안 작성 (한국어)
4. 썸네일 1장 + 본문 섹션 삽화 n장 생성
5. 게시 패키지 폴더 출력 (아래 구조)

```
~/Documents/BlogPackages/<YYYY-MM-DD>-<slug>/
├── post.md        # 티스토리 에디터(마크다운 모드) 붙여넣기용, 삽화 삽입 위치 표시
├── meta.md        # 제목(prefix 포함), 카테고리, 태그, 썸네일 설명
├── thumbnail.png
└── images/        # 본문 삽화 01.png, 02.png, ...
```

## Non-goals

- 티스토리 자동 로그인·자동 게시 (브라우저 자동화 — 접근 B, 추후 확장 과제)
- Notion MCP 없이 공개 링크만으로 읽기 (notion.site는 JS 렌더링이라 WebFetch로 본문 읽기 불가 — 2026-11-14 실측 확인)
- Claude Code 외 다른 harness(Codex 등) 지원
- 블로그 카테고리 신설·개편

## Anti-goals

- 원본에 없는 사실 추가·과장 (요약은 원본 사실 범위 내에서만)
- 계정 리스크를 만드는 자동화

## 제약

- 티스토리 Open API는 2024-02 종료 → 게시는 수동 붙여넣기 패키지로만
- 이미지 생성 API 키는 macOS Keychain에서 조회 (plaintext 저장 금지)
- 산출물·블로그 글은 한국어, 기존 블로그 문체 유지

## 검토한 접근

| 접근 | 내용 | 결정 |
|---|---|---|
| A. 게시 패키지 | 완성된 초안+이미지를 폴더로 출력, 수동 붙여넣기 | **선택** — 안전, 단순, 계정 리스크 0 |
| B. 브라우저 자동화 게시 | 카카오 로그인 → 에디터 조작 → 임시저장 | 보류 — 로그인·2FA 장벽, UI 변경 취약, 최후 수단 원칙 위배. A 안정화 후 확장 과제 |

사용자가 A를 선택함 (2026-11-14).

## 결정 사항

사용자가 결정:
- 게시 방식 A (패키지)
- 카테고리 체계: 기존 4개 유지 + 제목 prefix + 기술 분야 태그
- 썸네일 + 본문 중간 삽화 생성 포함

작성자(Claude) 판단 (수정 가능):
- 스킬 이름 `notion-to-tistory`, 위치 `~/.skills/skills/notion-to-tistory/` (my-agents-skills 레포)
- 노션 읽기: Notion MCP(`notion-fetch`)에 게시 링크 전달 — MCP 필수. 미연결 시 명확한 오류 안내 후 중단 (WebFetch fallback은 실측 결과 동작하지 않아 제거)
- 하네스 범위: Claude Code 전용
- 이미지 생성: Gemini 이미지 API(`gemini-2.5-flash-image`) — 사용자 확정(2026-11-14). 키는 Keychain에 `GEMINI_API_KEY` 서비스명으로 저장 후 `security find-generic-password`로 조회, 생성 스크립트는 스킬 내 `scripts/generate_image.py`. 키 미등록 상태에서는 이미지 단계에서 발급·등록 안내 후 중단
- 출력 위치 `~/Documents/BlogPackages/` (Notes 보호 경로 회피)
- 파이프라인: 읽기 → 분류 → 초안 집필 → 사용자 초안 승인 → 이미지 생성(비용 발생 단계이므로 승인 후) → 패키지 출력
- 삽화 스타일: 깔끔한 플랫 일러스트, 글당 본문 삽화 기본 2~3장 (섹션 수에 따라 조정)

## 빌더에게 남기는 것

- 분류·집필 프롬프트의 세부 문구 (기존 블로그 글 몇 편을 톤 레퍼런스로 참조할 것)
- post.md 내 삽화 삽입 위치 표기 방식
- 노션 페이지에 이미 있는 이미지의 처리 (다운로드해 images/에 포함할지, 생성 삽화로 대체할지 — 기본: 원본 이미지 우선 포함)
